# Collections Framework in Java

## 1. Для чого призначений Collections Framework?
**Collections Framework** у Java — це набір класів і інтерфейсів, які забезпечують ефективне управління групами об'єктів (колекціями). Основні переваги:
- Стандартизовані методи для роботи з колекціями.
- Зручність роботи з групами даних: додавання, видалення, пошук, сортування тощо.
- Підтримка різних типів структур даних: списки, множини, черги, словники.

---

## 2. В чому полягає різниця між масивами та колекціями?
| **Масиви**                            | **Колекції**                                                           |
|---------------------------------------|------------------------------------------------------------------------|
| Фіксований розмір після створення.    | Можуть змінювати розмір динамічно.                                     |
| Підтримують лише базові операції.     | Мають багатий набір методів (додавання, видалення, сортування тощо).   |
| Працюють тільки з одного типу даними. | Можуть працювати з дженериками, що забезпечує типобезпечність.         |
| Підтримуються на низькому рівні.      | Побудовані на основі стандартних класів і інтерфейсів.                 |

---

## 3. Які особливі властивості є у списків порівняно з іншими типами колекцій?
- Збереження **порядку елементів** (в тому порядку, в якому вони додавались).
- Доступ до елементів за індексом (наприклад, `list.get(index)`).
- Підтримка дублікатів (на відміну від множин, які не допускають дублікатів).

---

## 4. Чим списки відрізняються від масивів?
- **Розмір**: Масиви мають фіксований розмір, тоді як списки можуть динамічно змінювати розмір.
- **Гнучкість**: Списки мають готові методи для додавання, видалення та пошуку елементів.
- **Підтримка дженериків**: Списки дозволяють забезпечити типобезпечність даних через дженерики.
- **Інтерфейсна підтримка**: Списки реалізують інтерфейси `List` і можуть бути передані методам, які працюють з цим інтерфейсом.

---

## 5. Чим ArrayList відрізняється від LinkedList? Який з них у яких випадках краще використовувати?
| **ArrayList**                              | **LinkedList**                           |
|--------------------------------------------|------------------------------------------|
| Заснований на динамічному масиві.          | Заснований на зв'язаному списку.         |
| Швидкий доступ за індексом.                | Повільний доступ за індексом (O(n)).     |
| Додавання/видалення в кінці списку швидке. | Швидке додавання/видалення в середині.   |
| Більше підходить для операцій читання.     | Більше підходить для частих модифікацій. |

**Рекомендації:**
- Використовуйте `ArrayList`, якщо вам потрібен швидкий доступ до елементів.
- Використовуйте `LinkedList`, якщо ви часто додаєте або видаляєте елементи у середині списку.

## 6. Що таке Iterator? В чому полягають переваги використання ітератора?
**Iterator** — це інтерфейс, який дозволяє перебирати елементи колекції без розкриття її внутрішньої структури.

**Переваги:**
- Абстрагування деталей реалізації колекції.
- Можливість видалення елементів під час ітерації через метод `remove()`.
- Зручний для роботи з будь-якими колекціями.

**Порівняння з циклом `for`:**
- Використання ітератора є безпечнішим для модифікації колекції під час ітерації.
- Цикл `for` (`for (int i = 0; i < collection.size(); i++)`) не підходить для структур, які не підтримують доступ за індексом, наприклад, `Set`.
